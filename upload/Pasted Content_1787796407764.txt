# MASTER PROMPT PACK

## Armenian Legal Search Agent

### ARLIS live search + OpenCloud AI + Google-style Search UI

---

# 0. ROLE

You are the principal software architect, senior full-stack engineer, search engineer, AI-agent engineer, QA engineer, security engineer, and deployment engineer responsible for delivering a complete production application.

You are not producing a mockup.

You must build, test, verify, and deploy the real working system.

Project working name:

`Armenian Legal Search`

Primary purpose:

Create an extremely fast Armenian legal search website where a user asks a legal question and receives:

1. the **four most relevant primary-source results from ARLIS** at the top;
2. underneath those four results, a **streaming AI legal answer**;
3. every material legal proposition in the AI answer linked back to the retrieved ARLIS source.

The visual interaction model should be inspired by the simplicity of Google Search, but must NOT copy Google's trademarks, logo, proprietary assets, exact branding, or imply affiliation with Google.

The application must be optimized for Armenian legislation.

Primary source:

`https://www.arlis.am`

AI runtime/platform:

`OpenCloud / opencloud.ai`

All LLM reasoning for the application must go through the OpenCloud AI runtime.

Do not put OpenAI, Anthropic, OpenRouter, Gemini or any other provider API key directly into frontend code.

Do not create a parallel LLM backend unless explicitly authorized.

# 1. NON-NEGOTIABLE PRODUCT CONTRACT

The main interaction is:

```text
USER QUERY
   ↓
QUERY NORMALIZER
   ↓
LEGAL QUERY PARSER
   ↓
ARLIS SEARCH
   ↓
RETRIEVE CANDIDATES
   ↓
RANK / DEDUPLICATE
   ↓
TOP 4 PRIMARY SOURCES
   ↓
DISPLAY TOP 4 IMMEDIATELY
   ↓
FETCH RELEVANT SOURCE TEXT
   ↓
BUILD GROUNDED CONTEXT
   ↓
OPENCLOUD AI AGENT
   ↓
STREAM LEGAL ANSWER
   ↓
INLINE SOURCE CITATIONS
```

The page MUST NOT make the user wait for the LLM before showing search results.

The four search results and AI answer are separate layers.

Search is authoritative retrieval.

LLM is interpretation/synthesis.

The LLM must never substitute for the primary source.

Do NOT send the original question directly to the LLM and ask it to "find the law."

```text

    ↓

    ↓
```

# 6. ARMENIAN QUERY NORMALIZATION

Implement Armenian-aware normalization.

Support queries such as:

```text
ՔԴՕ 108
քդօ 108 հոդված
108 հոդված ձերբակալում

քր դատ օր 108
```

Normalize:

* Armenian Unicode;
* repeated whitespace;
* Armenian punctuation;
* quotation marks;
* article notation;
* common abbreviations;
* Arabic digits;
* Armenian legal abbreviations.

Maintain a controlled abbreviation dictionary.

Example:

```json
{
  "ՔԴՕ": "ՀՀ քրեական դատավարության օրենսգիրք",
  "ՔՕ": "ՀՀ քրեական օրենսգիրք",
  "ՔՔՕ": "ՀՀ քաղաքացիական օրենսգիրք",

}
```

Do not expand ambiguous abbreviations without retaining the original query.

# 7. LEGAL QUERY PARSER

Before search, parse the query into structured fields.

Target structure:

```ts
type LegalQuery = {
  raw: string;
  normalized: string;

  actTitle?: string;
  actType?: string;

  article?: string;
  part?: string;
  point?: string;

  caseNumber?: string;

  keywords: string[];

  date?: string;

  wantsCurrentLaw: boolean;
  wantsHistoricalLaw: boolean;

  questionType:
    | "exact_article"
    | "legal_rule"
    | "case_law"
    | "definition"
    | "procedure"
    | "unknown";
};
```

Examples:

Input:


Output:

```json

  "actTitle": "ՀՀ քրեական դատավարության օրենսգիրք",
  "article": "108",
  "part": "3",
  "questionType": "exact_article"
}
```

Input:

```text
Վճռաբեկ դատարանի դիրքորոշումը ձերբակալման անհապաղ դատական վերահսկողության մասին
```

# 12. SEARCH RANKING

The first four results must be determined by retrieval logic, NOT by the LLM.

Create deterministic ranking.

High priority:

```text
exact act + exact article
exact article match
exact legal act title
exact phrase
act number
case number
title match
article heading match
body phrase match
keyword overlap
current valid act
```

Illustrative scoring model:

```text
exact act + article       +100
exact article             +70
exact act title           +55
exact case number         +100
exact phrase              +40
title token match         +25
article heading match     +25
body keyword match        +10..30
current status            +10
```

This is a starting point only.

Tune with tests.

Do not blindly use these weights without evaluating relevance.

the AI answer MUST state that.

Never silently use today's provision for a historical event.

# 22. HALLUCINATION FIREWALL

Before returning final answer, validate all citations.

Algorithm:

```text

        ↓

        ↓
does source exist?
        ↓
```

```text

```

when only S1–S4 were provided.
